# 0011: Polyphony: a voice pool per synth

**Status:** Accepted · **Date:** 2026-10-03

## Context

Every synth is monophonic today: one Mono voice per owner (live keys, each MIDI channel), kept in `Engine::monos` with a `synth_of` map (ADR-0008, spec 004 Req 6, 10). Epic #78 adds seven polyphonic instruments (Prophet-5, Juno-106, Jupiter-8, Matrix-12, PPG Wave, Roland D-50, Yamaha DX7). They need several voices per synth, an allocator, stealing, a shared LFO, per-voice analog variance, and MIDI channels that play chords through the same voices as the live keys.

Four of them are subtractive and can run on the Mono voice; the PPG Wave and D-50 add a table oscillator; the DX7 is FM.

## Decision

**Each synth owns a voice pool, allocated in `Engine::new`; the monosynths are a pool whose voices belong to owners.**

- `poly.rs` holds `Pool`: `MAX_VOICES` (16) voices of an enum `PolyVoice` (the Mono voice now; the table and FM voices when they land), each with a little metadata: its owner, its note, its age, whether it is held. The enum has no heap data, so a model change rebuilds a pool's voices without allocating (ADR-0002).
- **The Mono voice is the per-note voice.** A poly model presses one key on a free voice; the voice's key stack of one, its envelopes, filters and oscillators are exactly the monosynth's. No second DSP path for the four subtractive instruments.
- **Mono models keep their rule:** one voice per owner, with note priority, legato and glide on that voice's key stack, so every monosynth renders exactly as before. A *poly* model (`Model::voices() > 1`) allocates a voice per note instead.
- **Allocation:** a note takes a free voice, rotating from the last one used so a released tail is not cut first; a note already sounding on its owner re-uses its voice. **Stealing:** when no voice is free (or the synth's polyphony or the global budget is full), the voice in release that has sounded longest goes first, else the oldest held note. A stolen voice restarts clean.
- **Unison** presses the same note on up to all voices with a detune spread; **analog variance** gives each voice a seeded static detune, a slow drift and a small cutoff offset, set once per block (control rate).
- **The LFO is shared**: the pool runs one LFO and sample-and-hold per block and every voice reads it, as the hardware's single LFO is the same for every voice.
- **Voice budget:** a global cap on sounding voices (`VOICE_BUDGET`, 64, measured against the 25% budget in `make bench`); a note past it steals the globally oldest releasing voice.
- **Owners:** a voice remembers its owner (live keys or a MIDI channel) and its note, so a note-off releases its own voice and live keys and channels on one synth do not release each other. Rerouting a channel releases its voices.
- A model decides its voice count and kind; the parameters stay per synth (`MonoParams`), shared by every voice of the pool.

## Consequences

- `Engine::monos` and `synth_of` give way to `pools: [Pool; SYNTHS]`; `note_on`, `note_off`, `all_off`, `route` and the player go through them. The C ABI does not change.
- 16 pools of 16 voices of about 1.2 KB each: about 300 KB, all allocated up front; only sounding voices cost CPU.
- Polyphonic playing from the computer keyboard works as keys are pressed together.
- The table oscillator (PPG, D-50) and the FM voice (DX7) are further `PolyVoice` variants with the same four methods.
- Wavetables and attack samples are generated by our own code at start; nothing from a ROM is shipped. The FM voice is written in Rust from the public DX7 format with Google's msfa (Apache-2.0) as reference; Dexed (GPL-3) is not used. `NOTICE` records it.

## Alternatives considered

- **A shared pool of voices across all synths.** Fewer voices in memory, but a voice would carry its synth and every voice's parameters would be looked up per note; the per-synth pool keeps a voice's parameters in one place. The global budget gives the sharing that matters.
- **A new polyphonic voice type per instrument.** Duplicates the oscillators, filters and envelopes four times. Rejected for the subtractive four.
- **Voices as `Vec`s grown on demand.** Allocates on the audio thread. Rejected (ADR-0002).
